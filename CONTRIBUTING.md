# Contributing

Use a branch and pull request. Describe the hardware revision, problem, change, test procedure, expected result, actual result, and limitations. Attribute adapted code, CAD, media, and schematics.

Run the two host-test commands in the root README. For ROS changes also run colcon build and colcon test in ros2_ws on the documented ROS distribution.

Do not commit Wi-Fi credentials, generated caches, ROS build/install/log directories, or unapproved manuscripts. Do not describe simulation, linting, or unit tests as hardware validation. Electrical changes require independent design review and staged bring-up.
